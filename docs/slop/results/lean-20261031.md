# Leanness: code size, resident code, native calls, and gsub depth, 2026-10-31

Wave 9 left the default build of `lua` with 1056 KB of code against the
reference's 217 KB, 844 KiB of it resident when `lua -e ''` exits, and
a peak of 1212 KiB for `lua -e ''`; the C-API build peaked at 2688 KiB
against the reference's 2564 (2602 in `just bench-capi`). This wave cut
the code, put the code a run needs first together, trimmed the C call
path and the embedding API's reference reads, and took `gsub`'s buffers
off the native stack.

Machine: the orb's 4-core Intel Xeon @ 2.60GHz, kernel 6.1. Runs pinned
to core 3 with `taskset`, rounds interleaved, benchstat. Builds are
ReleaseFast unless named. Base is 129f3cf (wave 9).

Headlines:

- Text: default 1056 KB to 654 (−38%), C API 1141 to 723 (−37%),
  ReleaseSafe 1034 to 671. Gone: std's stack-trace machinery (DWARF,
  ELF, sorting: 215 KB), unused `std.Io` functions (63 KB), one
  `std.fmt` instance per error-message call site (52 KB), unrolled
  library registration (9 KB).
- Resident code at the exit of `lua -e ''`: 844 KiB to 136 (C API 800
  to 156, ReleaseSafe 984 to 180), by linking the functions a short run
  calls first at the front (`src/order.ld`, `just order`).
- Peak RSS of `lua -e ''`: default 1212 KiB to 556, C API 2692 to 1892,
  the reference 2560 here (2624 in `just bench-capi`). The C-API build
  is under the reference's floor; the default build is under a quarter
  of it.
- bench/ against the reference (`bench-compare-wave10-20261031.md`):
  ReleaseFast −28.4% time and −60.6% peak RSS (wave 9: −28.6%,
  −44.1%), ReleaseSafe −20.1% and −58.0% (wave 9: −18.7%, −36.3%), the
  C-API build −28.2% and −24.9%.
- A call of an empty C function, a loop iteration: 14.4 ns to 12.1
  (the reference 9.6). bench-api `zig_calls_lua` 22.5 ns to 18.6
  (−17.6%): two store-forwarding stalls gone.
- Nested `gsub` replacement functions reach 197 levels (base 74, the
  reference 197) within the unchanged 192 KiB budget; `gsub`'s frame
  2048 bytes to 368, `Parser.body`'s 416 to 176.
- Speed against the base, averaged over 16 stack placements: default
  +0.8% (its loop byte for byte the same), C API −3.1%.

What each piece was:

- **Panics.** Any `@panic` or safety check in a release build reached
  `std.debug.defaultPanic`, which prints a stack trace: the DWARF
  reader, the ELF loader, a decompressor, and `std.sort` instances for
  line tables, 215 KB together, and `.eh_frame` (50 KiB of read-only
  data) for the unwinder. Release builds of `lua` now print the panic
  message and abort (`main.zig`'s `releasePanic`), and the executable
  links without unwind tables; Debug keeps both.
- **`std.Io.Threaded`.** `std.process.Init` hands `main` the global
  `Threaded` instance, whose vtable names every function it implements,
  so all of them link: sockets, name lookup, memory maps, file locks,
  futures and groups. `main` takes `Init.Minimal` and builds its own
  `Threaded` with a vtable that points the 61 entries nothing calls at a
  function that panics with the entry's name: 63 KB.
- **Error formatting.** `Thread.raise`, `runError`, `debuginfo.raise`,
  and `Parser.fail` were generic over a format string and arguments, so
  each of their 108 instances inlined `std.fmt`'s formatting of its own
  argument tuple. They are now thin generic wrappers that pack the
  arguments into `Thread.FormatArg`s (string, integer, character,
  float) and call one non-generic formatter: 52 KB.
- **Library registration.** Each library's `open` unrolled one
  `setField` call per function; `auxlib.newLib` now loops over a
  comptime list in read-only data (`luaL_Reg`'s shape): 9 KB. The
  string metamethods share one `arith` with a run-time operator, and
  `auxlib.metafield` takes a run-time name.
- **The interpreter loop's two instances.** The unhooked loop is 28 KB
  and the hooked one 34 KB. They stay: merging them puts a hook check
  on every instruction of every run (wave 3's decision, `vm.md`). The
  hooked instance is now cold (`@branchHint(.cold)` when `hooked`), so
  it gets a `.text.unlikely.` section and the linker script below keeps
  it out of the code a run touches: it is resident only under
  `debug.sethook`.
- **Inlining and comptime tables.** Not large: read-only data is 122
  KB (base 170), the biggest tables are the lexer's and libm's (a few
  KB each). The two float formatters (`number.formatFloat`, 5.9 KB, and
  `lib.format.formatFloat`, 3.9 KB) and `std.fmt.parse_float` (4.8 KB)
  are left; merging them is a correctness project of its own.

The text that remains is mostly ours: the compiler (Parser, Code,
Lexer: 77 KB), the loops (62 KB), the libraries (os 35, io 31, base 28,
package 21, string 40), `std.Io`'s file functions (52), and in the C-API
build the API (54) and glibc's startup.

## What is resident, and the linker script

Resident code was the larger cost, and cutting text alone barely moved
it. The kernel maps an executable's file pages 64 KiB at a time around
each page that faults (`fault_around_bytes`), and `MADV_RANDOM` does not
turn that off for file mappings on 6.1. The functions `lua -e ''` calls
were spread through the whole text, about one per 64 KiB, so nearly all
of it was mapped: 844 of 1032 KiB in the base build, 580 of 640 after
the cuts above.

`src/order.ld`, generated by `just order` (`test/order/main.zig`), puts
the functions a short run calls first at the front of the code, in the
order they are first called. The tool runs `lua` under ptrace with a
breakpoint on every function's entry, for `lua -e ''` and then
`test/order/sample.lua` (strings, tables, sort, gmatch, gsub, pcall,
metatables, os.time), in the default and C-API ReleaseFast builds and
the ReleaseSafe build, in the dev shell's environment (dozens of
variables, and `LUA_PATH=;;`, which makes startup expand package's
default paths, as many installs have it). Release builds link with
`-ffunction-sections` and the script, which `INSERT`s a `.text.hot`
output section before `.text`:

- each function is listed as an input-section pattern, generic instance
  numbers as wildcards so edits that renumber them keep the script
  valid;
- where several functions share a pattern, the cold variant is listed by
  exact name, so the hooked loop's `.text.unlikely.vm.runLoop__anon_N`
  stays out while the plain loop's wildcard matches;
- crt1.o's `_start` (plain `.text`) and, in the C-API build, the PLT
  (`.plt : { *(.plt) }`), which startup calls, move up too.

A stale script costs memory, not correctness: a function it does not
name links where it did before. 313 patterns and crt1.o make 279 KiB
of hot code in the default build (C API 285, ReleaseSafe 293), of which
`lua -e ''` keeps 136 KiB resident.

## The C call path

`CALL` sent a native function (`native_fn`) straight to `callNative`,
but a native closure through `preCall`, which looks the callee up
again, dispatches on its type, and calls `callNative` itself. In a
C-API build every C function is a native closure (the trampoline and
the C pointer), so every call into C took the long way. The C-API
build's `CALL` now sends both to `callNative`, choosing the function
pointer with a select. The default build keeps its single test: the
second shifted its loop's registers (bench/patterns +2.3% over 16
stack placements), and the default build's native closures are only
bound Zig functions, for which the direct path is worth 1.2 ns a call
(bench-api `lua_calls_bound` 15.1 to 13.8 ns while it was in).

bench/capi's `calls.lua`, 10 rounds of 10M calls, CPU ns per iteration
of the loop (the empty loop is 3.4 ns ours, 4.4 the reference's):

| scenario                           | reference |  base | before `CALL` | after `CALL` |   new |
| ---------------------------------- | --------: | ----: | ------------: | -----------: | ----: |
| `nop`: an empty C function         |      9.65 | 14.36 |         14.59 |        12.07 | 12.08 |
| `add`: two integers in, one out    |     23.50 | 28.92 |         26.52 |        26.39 | 26.10 |
| `callback`: C calls a Lua function |     30.63 | 53.20 |         54.54 |        51.67 | 51.34 |

Net of the loop, an empty C function costs 8.6 ns against the
reference's 5.2 (base 10.9). What is left, by a profile of `nop`: the
loop's `CALL` handler and dispatch 2.6 ns over the empty loop,
`callNative` 2.8 ns (the stack and frame checks, the frame push, the
hook tests, the result move, the collector check), and the C API's
protected call per C function 2.6 ns (`capi.trampoline` and
`jmp.callNaked`, the register save that lets `lua_error` unwind; the
design is in `../c-api.md`). A Zig native function is cheaper than the
reference's library call: `coroutine.isyieldable` 9.1 ns an iteration
against 12.6 (net 5.7 against 8.2), the same in both of our builds.
The C → Lua level of native stack is 672 bytes (base 656, the
reference 351): the 16 bytes are the C-API loop's frame.

## The embedding API's reference reads

`api.refValue`, which every call through a `lua.Ref` reads, returned
`.nil` for the nil reference and the registry slot otherwise. LLVM
built the two candidates in memory and read the chosen one with one
16-byte load, right after writing the slot's value as two narrower
stores: a store-forwarding stall on every call, the one wave 9 took out
of `Table.get`. It now keeps one payload and one tag variable and
builds the value once (the hot-path rule in `plan.md`). Second,
`Thread.npcall` and `native_calls` were adjacent `u16`s; LLVM merged
their increments in `pcallMsgh` into one 32-bit load and store after the
16-bit stores of their separate decrements, another stall on every
protected call from the host. `npcall` is a `u32` now.

bench-api, 10 rounds, the API arm (ns per call; "before" is the tree
just before these two, with two loop changes since dropped, "after"
adds them):

| scenario             |  base | before | after |   new |
| -------------------- | ----: | -----: | ----: | ----: |
| `zig_calls_lua`      | 22.52 |  22.49 | 19.64 | 18.56 |
| `zig_calls_lua_notb` | 22.72 |  22.83 | 19.12 | 18.32 |
| `call_values`        | 27.05 |  26.94 | 23.88 | 23.61 |
| `globals`            | 20.87 |  20.28 | 21.41 | 22.05 |
| geomean of all 10    | 24.33 |  24.08 | 23.11 | 23.01 |

`globals` is 75% interning the name "counter" twice an iteration
(`std.mem.eql`, `wyhash`, `Interner.create` in a profile); its +1.2 ns
is where those landed. The internal arm, which reads the registry
directly and calls `vm.pcall`, moved by layout (geomean +0.85%;
`zig_calls_lua` +4%, from the step that resized `npcall`, which moved
`Thread`'s fields).

## Native stack: the loop, the compiler, gsub

Frames, bytes (pushes, `sub rsp`, return address; `objdump`):

| function             | base | new | base C API | new C API | base Safe | new Safe |
| -------------------- | ---: | --: | ---------: | --------: | --------: | -------: |
| `vm.runLoop`, plain  |  272 | 272 |        272 |       288 |       304 |      304 |
| `vm.runLoop`, hooked |  288 | 288 |        288 |       288 |       320 |      320 |
| `Parser.body`        |  416 | 176 |        416 |       176 |       432 |      176 |
| `string.gsub`        | 2048 | 368 |       2048 |       368 |      2080 |      400 |

**gsub.** A replacement function that calls `gsub` nests `gsub`,
`call1`, `callYieldable`, `callNative`, and `runLoop` per level, and
`gsub`'s own frame held an `auxlib.Buffer` (1 KiB inline) and a
`pattern.Matcher` (its 32 captures), 2048 bytes of the about 2.6 KB a
level took: within wave 9's 192 KiB budget (`Thread.max_native_stack`)
nesting stopped at 74 levels, where the reference reaches 197. The
owner's preferred fix was a smaller inline buffer and matcher, but the
fixed frames on the path are about 480 bytes a level (`runLoop` 272,
`callNative` 80, `call1` 96, `callYieldable` 48) against the budget's
998 for 197 levels, so the buffer and matcher would have to shrink to
about 500 bytes together, a 64-byte buffer and 8 captures where Lua
allows 32. Instead the two live in a block on the heap, `GsubScratch`:
the state keeps one block (`State.gsub_scratch`, 1.7 KB, freed with the
state) for the outermost `gsub`, and a nested call, which finds it
taken, allocates its own and frees it on return. `Buffer.initIn` and
`Matcher.reset` initialize them in place. The inline buffer stays 1
KiB, so `format`, `concat`, and the rest do not change, and a `gsub`
that does not nest allocates nothing after the first.

Nested `gsub` now reaches 197 levels in ReleaseFast, default and C-API
(the reference 197); 183 in ReleaseSafe, whose frames are larger. With
the replacement an `__index` function (cstack.lua's second case), 161
(C API 159, Safe 154; reference 197): the metamethod call adds frames
the plain case does not have. The budget is unchanged, so a 256 KiB
host thread still gets a Lua error on every hostile script of the fuzz
campaign (`fuzz repro grammar F --stack 256`, 31 of 31), and `ulimit -s
256` gives the same output as an unlimited stack.

**The compiler.** Every level of nested function bodies put a
`FuncState` (264 bytes: its seven growing lists and their counts) in
`Parser.body`'s frame; it is now allocated with the compiler's
allocator and freed when the body closes: 416 bytes to 176 per level.
Compile time does not move (bench/config, below).

**The loop.** The plain loop's 272 bytes are 48 of saved registers and
216 of slots: about 64 bytes of spills for the loop's own state (the
thread, the frame, `base`, constants, the closure), which every handler
reloads, and two dozen 8- and 16-byte temporaries of slow paths, each
used by two or three instructions. A `GETVARG` that writes its result
field by field instead of choosing among three whole values took 16
bytes off, and cost bench/methods 4.7% averaged over 16 stack
placements (below), as any change to the loop shifts its registers; it
was not kept. The C-API build's plain loop is 16 bytes larger than
before for its direct C call (next section).

## Speed

The bench/ timings in this wave moved with something no change
touched: where the initial stack lands. The base binary ran
bench/methods 8.7% slower with an empty environment than in the dev
shell, and a 30 KB variable did not move it (`abenv` below). So the
A/B runs below average over stack placements: every program, on every
arm, runs under 16 environment sizes (a variable of 0 to 3840 bytes in
steps of 256), arms interleaved and rotated, pinned to core 3, n = 16
or 32 per row (`abpad.sh`). The earlier plain 10-round runs had ±10%
spreads that hid these effects.

The whole wave, every bench/ program, against the base (n = 16 each):

| arm         | geomean vs base default | rows slower (p < 0.05)                                                                         |
| ----------- | ----------------------: | ---------------------------------------------------------------------------------------------- |
| new default |                  +0.78% | json +2.9, patterns +2.6, closures +2.2, template +1.9, coroutines +1.2, format +1.0           |
| base C API  |                  +3.73% | (the C-API build's loop has one register fewer, `c-api-20261031.md`)                           |
| new C API   |                  +0.51% | concat +2.8, coroutines +2.3, json +1.9, fib +1.7, hash_string +1.7, array +1.5, closures +1.3 |

The C-API build is 3.1% faster than before (base C API to new C API:
globals −12.6%, closures −8.9%, methods −11.5%, oop −5.8%); the default
build is 0.8% slower with its loop byte for byte the same.

By step, on the programs each could touch (same method; "s0" is the
two committed size changes, before anything else):

- Size cuts (base → s0, loop identical): methods +2.6%, json +1.0%,
  the rest level (`abpad1`, `abpad3`). No code on these paths changed;
  the functions around them moved.
- The direct C call, in the default build as first written (s0 → s1):
  patterns +2.3%; dropped from the default build.
- `GETVARG` field by field (s1 → s2): methods +4.7%, patterns +1.8%;
  dropped.
- `refValue` and `npcall` (s2 → s3): bench/ level; bench-api above.
- `FuncState` on the heap (s3 → s4): config, json, template level
  (n = 32); format +1.0%.
- gsub's scratch block (s4 → s5): patterns −2.4%, concat −1.7%,
  template −0.4%, table_concat +3.4%, format level. `string.format`
  and `table.concat` do not use the block; table_concat's +3.4% is
  placement, as the next row's −4.1% for the same code shows.
- The linker script (the same tree without it → new), every program
  (n = 16): default −0.25% (table_concat −4.1%, methods −3.2%, format
  +2.2%, closures +1.6%, template +1.3%), C API +0.15%.

The default loop's code is wave 9's: `objdump` of the plain instance,
addresses masked, differs from the base only in the alignment padding
after its last instruction.

## Rejected or left

- **`MADV_RANDOM` on the executable** to stop fault-around: kernel 6.1
  still maps around faults in file-backed text.
- **Ordering by module** (whole object files): too coarse; the code a
  run needs is a few functions of most modules.
- **Only splitting `.text.unlikely` off** (cold functions last): 48 KiB
  less resident, against 708 for the full order.
- **Naming the hooked loop by a wrapper.** `@call(.always_inline,
runLoop, .{th, true})` in a `runLoopHooked` gave it a name of its own
  and a 1072-byte frame (ReleaseFast), as Zig's inline call lost the
  lifetimes the generic instance has; a plain call is not inlined by
  LLVM, so the name stays `runLoop__anon_N`. The cold hint does it
  without touching the plain loop's code.
- **The direct C call in the default build.** Testing for native
  closures in `CALL` lets bound Zig functions (`state.function`) skip
  `preCall` too, but shifted the default loop's registers: bench/patterns
  +2.3% averaged over stack placements. The default build keeps its one
  test; the C-API build, where C functions are native closures, has
  both.
- **A `GETVARG` without whole-value selects**: −16 bytes of loop frame,
  bench/methods +4.7% (the loop section above).
- **A hand-written trampoline in assembly** for C functions: at most 1
  ns of the C call, against a second copy of the error protocol to keep
  in step.
- **Moving the GC check out of `callNative`**: changes when a collection
  can run relative to the reference.
- **Shrinking `Buffer` and `Matcher` for gsub's depth**: cannot reach
  197 levels with Lua's 32 captures (the gsub section above).

Left for the next waves:

- The hooked loop (34 KB) could share code with the plain one only by
  checking hooks per instruction; it is out of the resident set now.
- Two float formatters and std's float parser (15 KB) could be one.
- The C-API build's floor is glibc's: ld.so and libc.so map about 1.3
  MiB that the static default build does not.
- Bench timings move with the initial stack's placement: bench/methods
  by up to 8.7% on the same binary between an empty environment and the
  dev shell's. Comparisons here average over 16 environment sizes
  (`abpad.sh` below); `bench-compare` does not yet.

## Raw output

```bash

  for pad in $(seq 0 256 3840); do
    p=$(head -c $pad /dev/zero | tr '\0' x)
    for prog in $progs; do
      for i in $(seq 0 $(( n - 1 ))); do

        printf 'BenchmarkLua/%s\t1\t%d ns/op\n' $prog $(( (e - s) * 1000 )) >> $out/$arm.txt

    done
  done
done
```
