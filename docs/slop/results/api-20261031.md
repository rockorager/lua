# Embedding API against the internal path, 2026-10-31

What a call through the embedding API (`src/api.zig`) costs against the
same work written on the engine directly, the way the standard library and
the standalone `lua` write it: natives on `stack[base..top]` with
`auxlib.Args`, `vm.pcall` from the top level, raw table operations, and a
userdata type check against a metatable found in the registry by name.

## Method

`just bench-api 10`: `bench/api/main.zig` built ReleaseFast, one process per
(arm, scenario), 10 interleaved rounds with the arm order rotating, pinned
to the last core with `taskset`. Each process times its loop with the
monotonic clock and prints ns per operation; GNU time's `%M` gives its peak
RSS. Both arms print the work they did to stderr, and the recipe fails if the
arms differ. Intel Xeon @ 2.60GHz (the orb's), Zig 0.16.0.

| Scenario             | Operation                                                        |   N |
| -------------------- | ---------------------------------------------------------------- | --: |
| `lua_calls_zig`      | Lua calls a Zig function `add(a, b)` of two integers             | 20M |
| `zig_calls_lua`      | the host calls a Lua function of two integers from the top level | 10M |
| `zig_calls_lua_notb` | the same with `Options.traceback` off                            | 10M |
| `callback`           | Lua calls a Zig function that calls a Lua function back          |  5M |
| `globals`            | the host sets an integer global and reads it back                | 10M |
| `userdata_method`    | Lua calls `c:incr()` on a userdata                               | 20M |
| `decode_struct`      | the host reads a four-field table into a struct                  | 10M |

## Result

The API costs what the internal path costs or less: geomean 7.7% faster,
with peak memory identical. Lua calling Zig is 26% faster and userdata
methods 12% faster, because the generated wrappers check the exact type
inline and push results without translating errors, which the
hand-written `auxlib.Args` natives do not. The one regression is
decode_struct, 5.2% (2.3 ns per four-field decode); both arms spend most of
it interning the field names.

An API state allocates 131 bytes more than the engine's state with the same
libraries (11,238 against 11,107 heap bytes after opening `safe_libs`): the
userdata type table and its registry key. The API's `Extra` (the libraries'
4,200-byte `base.Host`, the traceback buffer) comes from the host's
allocator, as an internal host's `Host` does.

### The userdata type check

Finding `T`'s metatable for a type check, measured on the API arm only:
`array` reads it from `Extra.types` at `T`'s number (what landed);
`registry` looks it up in the registry under a light userdata key per type,
`luaL_checkudata`'s shape. Same method, 10 interleaved rounds, pinned.

```
                    │    array    │              registry               │
                    │   sec/op    │   sec/op     vs base                │
API/userdata_method   41.51n ± 3%   57.60n ± 4%  +38.76% (p=0.000 n=10)
```
