# The wave-2 VM against the core, 2026-10-30

What wave 2's VM work (`../vm.md`) did to speed: the core's `fib`, `loop`,
and `tab` programs from `core-baseline-20261030.md`, and the `bench/`
programs that exercise what changed. Base is `main` at 7f71f7e (the core,
the compiler, and the libraries, before this work); new is the `wave2-vm`
branch; ref is reference C Lua 5.5.1 from the dev shell.

## Method

- Wall time: `zig build -Doptimize=ReleaseFast` of each tree, the three arms
  interleaved round by round in a rotating order, pinned to the last core
  with `taskset`, 10 rounds, whole processes, compared with benchstat. The
  core programs are the baseline's sources run by the standalone `lua`
  (`core_fib`, `core_loop`, `core_tab`). The orb is shared and noisy
  (spreads up to ±20%), so instruction counts back the wall times.
- Instructions: `-Dcpu=x86_64_v3` builds of the same trees under
  `valgrind --tool=callgrind` (total `Ir`), smaller inputs where noted.
  These are deterministic, so a difference of a few percent is real.

## What changed on the hot paths

1. `SETFIELD` on a table with a metatable stores in place when the key is
   present (`Table.replaceShortStr`); before, every `self.x = v` went
   through `setSlow`'s raw get and raw set.
2. `GETFIELD`/`SELF` that miss look the key up in an `__index` table
   inline: one level of method lookup without `getSlow`.
3. An arithmetic fast path that skips its `MMBIN` fetches the instruction
   after it directly (`fetchSkip`). Before, `pc += 1` followed by the
   shared fetch made the compiler copy `pc` through a scratch register:
   three instructions instead of one in every `ADD`.
4. `CONCAT` builds a result of at most 40 bytes in one pass, formatting
   each number once.
5. `vm.get`'s fast path, `vm.toNumber`, and `vm.toInteger` are inline, so
   natives such as `ipairs`' iterator do not pay a call for them.

The full `bench/` set, run earlier against `main` at bb38f87 with the
same hot-path code (one round overlapped a build, so its spreads are
wider), showed the rest unchanged: binary_trees, closures, hash_int,
hash_string, mandelbrot, patterns, spectral_norm, and table_concat within
noise; nbody −20% (its objects' fields go through change 1); coroutines,
which base cannot run, at 0.60× the reference.

## Reading it

- `methods` went from 1.45× the reference to parity, and `nbody` lost a
  fifth; both are field stores and method lookups on objects with
  metatables.
- `loop` runs 12% fewer instructions; its wall time is within noise of
  base and 0.72× the reference.
- `fib` runs 4% fewer instructions but measured 6–9% slower in wall time,
  twice, against base (the reference sits between them). The instruction
  listings of `CALL` and `RETURN1` explain it: the larger `execute` spills
  two values the call path uses (`mov -0x30(%rbp)` reloads after the
  dispatch jump, and a spill store in `CALL`), so loads land on the call
  path's dependency chain. Moving cold code out of `execute` to give the
  register allocator room is the follow-up; it is not done here.
- `format` runs 2% more instructions: `CONCAT` is now an out-of-line call
  (`concatValues`, which also serves `__concat` and the native API) where
  base inlined it, and string.format's inlined helpers moved; its wall
  time is within noise.
