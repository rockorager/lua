# Full C API coverage: costs (wave 11, the API part)

Wave 11's API part took the C API from 128 of 156 functions to all of
them, added `liblua` for C hosts, made `luaL_Buffer`'s box reallocate in
place, and took the store-forwarding stall out of the API's index
lookups. The design is in `../c-api.md`. Machine: the orb's 4-core Intel
Xeon @ 2.60GHz, runs pinned to core 3 with `taskset`, arms interleaved,
benchstat. Builds are ReleaseFast. Base is 3e3d9b8 (wave 11's io part
merged), rebased onto.

## The default build is unchanged

- `.text.hot` (287069 bytes) and `.text` (366848) of the default `lua`
  are byte for byte 3e3d9b8's (`objcopy -O binary --only-section`, then
  `cmp`), so both `vm.runLoop` instances are too, and bench-compare has
  nothing to compare. `.rodata` is the same size.
- Two library changes would have touched it: `warn` going through the
  state's warning function (+14 bytes) and `debug.gethook` answering
  "external hook" for a C hook (+127 bytes). Both are behind
  `Thread.prefix_len != 0`, which is comptime false there.

## The C-API build

Its two `runLoop` instances are byte-identical to 3e3d9b8's C-API build
(15,774 lines each; `objdump -d --no-show-raw-insn`, addresses, symbols
and `__anon` suffixes masked).

### The floor and `src/order.ld`

Before the rebase, `lua -e ''` with `-Dc-api=true` peaked at 2256 KiB
after the coverage work, against 1892 at b647dab: the `luaopen_*` exports
call each library's `open`, so the compiler stopped inlining `lib.*.open`
and `process.Environ.createMap` into startup, and the order script, which
names functions, did not list them, so fault-around mapped 184 KiB more
code. `just order` lists them. After the rebase it ran again: 340
functions.

- **callback −21%** (C → `lua_call` → Lua, 50.2 to 39.4 ns; the
  reference: 32 ns). capi's `at` returned the value at an index as a
  `?Value`, 24 bytes returned through memory: the callee's stores of the
  tag and payload, then the caller's wider loads of them, stalled on
  store forwarding at every `get`. It returns a pointer to the slot now
  (the registry's from a per-thread scratch value); `lua_compare` and
  `lua_rawequal` copy the values before anything can move the stack.
- The trampoline now closes a returning C function's to-be-closed slots:
  one load and compare of the thread's to-be-closed count, and nop is
  level. The protected call per C function is still ~2.5 ns over the
  reference's empty call.

### `luaL_Buffer`'s box and `read("a")`

The box now holds a pointer to heap memory that grows with `realloc`
(`mremap` for large blocks), freed by `luaL_pushresult` or, after an
error, its `__gc`; it was the bytes in a userdata, copied into a new one
1.5× larger at each growth. With it, the `statx` hint `readAll` used to
size its buffer stopped paying, so it went. Three arms, 10 rounds:
`hint` is the new box with the hint, `nohint` without.

```
           │     ref     │                 hint                 │                nohint                │
           │   sec/op    │    sec/op     vs base                │    sec/op     vs base                │
Io/all       199.4m ± 9%   323.4m ±  9%  +62.14% (p=0.000 n=10)   302.7m ± 16%  +51.80% (p=0.000 n=10)
           │ peak-RSS-KiB │ peak-RSS-KiB  vs base                │ peak-RSS-KiB  vs base                │
Io/all        63.34k ± 0%    62.80k ± 0%   -0.86% (p=0.000 n=10)    63.03k ± 0%   -0.49% (p=0.000 n=10)
```

The old box without the hint took 560.8 ms and 107.7 MiB
(`c-api-io-20261031.md`). What is left against the reference is page
faults: 202,000 minor faults for 20 reads against its 101,000 (GNU time
`%R`). Each read maps a fresh 20 MB box and a fresh 20 MB string, which
our page allocator unmaps on free; glibc raises its mmap threshold after
the first large free and serves the next reads from memory it already
faulted in. Building the string in the box's block would save one of the
two.
