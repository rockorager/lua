# Line information in luac's encoding, 2026-10-31

`Proto.lineinfo` held one absolute `u32` line per instruction, and
`string.dump` re-encoded it into luac's format. luac keeps a signed byte
per instruction, the change from the previous instruction's line, plus
an absolute `(pc, line)` entry where the change does not fit in a byte
or after 128 relative bytes in a row (lcode.c's `savelineinfo`,
`MAXIWTHABS`). Wave 6 found the difference costs about 3 bytes per
instruction, 185 KiB of `bench/config.lua`'s 521 KB chunk.

## The change

- `Code.zig` builds luac's encoding as lcode.c does: `saveLineInfo`
  (`savelineinfo`) after each instruction, `removeLastLineInfo`
  (`removelastlineinfo`) when the last instruction is dropped, and
  `fixLine` (`luaK_fixline`) as remove-then-save, so an instruction moved
  back from an absolute entry is forced absolute as in luac. `Proto`
  holds `lineinfo: []i8` and `abslineinfo: []AbsLineInfo`.
- `Proto.lineAt` is `luaG_getfuncline`: from the last absolute entry at
  or before the instruction (found from the estimate `pc / 128 - 1`, as
  the reference does), plus at most 128 bytes. On a loaded chunk, whose
  entries nothing checks, it stays in bounds whatever they hold.
- The line hook uses `Proto.changedLine` (ldebug.c's `changedline`),
  which adds the bytes between two instructions under 64 apart instead
  of decoding both lines; `debug.getinfo`'s `activelines` walks the
  bytes once with `Proto.nextLine` (`nextline`).
- `dump.zig` writes both arrays as they are and `undump.zig` reads them
  as they are. That closes the one divergence `dump.md` recorded: a call
  whose parentheses enclose 128 lines or more was saved at an absolute
  line, then moved back by `luaK_fixline` and forced absolute, which a
  replay of the final lines could not see. `test/diff/dump.lua` now has
  that case (the previous build's dump differs from the reference's
  there; this one's is the same).

`just bytecode` lists 54 of 54 files as luac does (the listing prints
each instruction's line through `lineAt`), `just dump` matches 108 of
108, `just diff`, `all.lua`, and every suite file alone pass.

## Scripts

`cfgcompile.lua` is `bench/config.lua` up to `local source =
concat(out)`, then:

```lua
collectgarbage() collectgarbage()
local before = collectgarbage("count")
local f
for i = 1, 64 do f = assert(load(source, "=config")) end
collectgarbage() collectgarbage()
print(#source, string.format("%.0f KiB held by one compiled chunk", collectgarbage("count") - before))
```

`loadall.lua FILE...`:

```lua
collectgarbage() collectgarbage()
local before = collectgarbage("count")
local keep = {}
for i = 1, #arg do keep[i] = assert(loadfile(arg[i])) end
collectgarbage() collectgarbage()
print(string.format("%d files, %.1f KiB", #arg, collectgarbage("count") - before))
```

`linehook.lua`:

```lua
local n = 0
debug.sethook(function() n = n + 1 end, "l")
local s = 0
for i = 1, 1e6 do
  s = s + i
  if i % 3 == 0 then
    s = s - 1
  end
end
debug.sethook()
print(n, s)
```

`errpos.lua`:

```lua
local function f(i)
  local t = {}
  for j = 1, 3 do t[j] = i + j end
  error("x" .. t[1])
end
local c = 0
for i = 1, 3e5 do
  local ok, m = pcall(f, i)
  c = c + #m
end
print(c)
```

The A/B runs used a copy of `bench-compare`'s loop over these scripts
(arms rotated each round, `taskset` to the last core, GNU time's `%M`),
and `bench-compare` itself with the base build first on `PATH` as `lua`.
