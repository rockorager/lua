# Hooks without a cost when unset, 2026-10-30

What adding debug hooks (`../vm.md`, "Hooks") did to the interpreter's
speed with no hook set. Base is `main` at 8006d92; new is the
`wave3-hooks` change: `vm.execute` runs one of two instances of the loop,
and only the hooked one traces instructions. The unhooked instance checks
the hook mask only after call-outs (natives, metamethods, `__close`
handlers, collection), not per instruction and not on Lua-to-Lua calls
and returns.

## Method

`zig build -Doptimize=ReleaseFast` of each tree. Ten rounds, both arms
interleaved in a rotating order, pinned to the last core with `taskset`,
whole processes, wall time from bash's `EPOCHREALTIME` and peak RSS from
GNU time's `%M`, compared with benchstat. Programs: `core_fib`
(`fib(32)`, the core baseline's), `loop` (a 10^8-iteration numeric `for`
adding to a local), and `bench/fib.lua` (`fib(35)`). The orb is shared,
so spreads are a few percent.

## Reading it

- No cost: `loop` is within noise, and both `fib` rows came out 4–6%
  faster. The hooked instance doubles `execute`'s code, but the unhooked
  one is the only one that runs, and its dispatch is the wave-2 loop's.
  The `fib` gain is code layout, not a mechanism; read it as "no
  regression", not as a speedup.
- Peak RSS is unchanged (2.4 MB on all three).
